# 글로벌 포지션 일보 연동 v0.3.79

대상 화면: 시장스캐너 → 시황일보 → 해외 커뮤니티. 기존 국내 커뮤니티의 루트 `latest.*`, `reports/`와 59채널 작업은 그대로 사용한다. 새 보고서는 모두 `global-position/` 아래에 둔다.

| 경로 | 용도 |
|---|---|
| `global-position/latest.json`, `latest.md` | 원문을 확인하고 작성한 한국어 종합판단 |
| `global-position/reports/YYYY-MM-DD.json`, `.md` | 날짜별 발행본 |
| `global-position/discovery/latest.json`, `latest.md`, `reports/` | 공개 RSS 후보, 본문 분석과 구분 |
| `scripts/global_position_contract.py` | 보고서 검증 및 해시·Markdown 생성 |
| `scripts/validate_global_position.py` | 발행 전 검증 명령 |
| `docs/GLOBAL_POSITION_TASK.md` | 정기 보고서 작성 지침 |
| `schema/global_position_v1.schema.json` | 필드 규격 |

## 작성과 취합

한국시간 오전 8시 무렵 GPT 작업을 시작하여 검증과 발행을 마친 뒤 프로그램에 반영한다. 오전 8시는 분석 완료 시각이 아니다. 최초 10월 16일 검증 일보는 최근 24시간의 새 자료 2건과 이전 관점 4건을 분리했다. 설치물의 테스트용 초기 기준자료와 실제 발행본을 혼동하지 않는다.

정기 보고서는 실제 실행 시각 기준 최근 24시간의 새 자료를 `entries`로, 이전 관점은 최대 30일의 `context_entries`로 구분한다. 과거 기사 재전송·검색 수집 시각을 새 발언 시각으로 사용하지 않는다. 게시시각을 확인하지 못하면 날짜만 남긴다. 일일 경계의 날짜만 확인한 기사는 새 판단의 근거로 승격하지 않고 이전 자료 또는 미검증 후보로 남긴다.

핵심 대상은 Shawn Tuteja(Goldman Sachs ETF·맞춤형 바스켓 변동성), Michael Hartnett(BofA 전략·Flow Show), PIMCO(운용기관, Ivascyn·Balls·Wilding 등)다. 3명의 헤지펀드 매니저로 분류하지 않는다. 추가로 프라임브로커 롱·숏/총노출/순노출, 롱 청산과 쇼트커버, CTA·변동성 목표·딜러 감마, 펀드 자금흐름, 국채 베이시스·레포·마진·캐리를 검색한다.

공식 발표·인터뷰를 우선하고 언론·공개 커뮤니티의 언급도 수집한다. 기사 제목만 확보한 자료, 유료 본문 미확인, 원본 은행 메모 미확인을 밝힌다. 커뮤니티 주장은 독립 검증 전에는 시장 방향의 근거로 사용하지 않는다. 동일 은행 메모를 재전송한 기사들을 여러 독립 증거로 집계하지 않는다.

종합판단은 글로벌 주식 매수·매도 압력, AI·반도체 포지션, 금리·조달·유동성, 한국장 전달 경로의 네 항목이다. 근거/반대 근거/신뢰도/확인 한계를 함께 제시한다. 자산배분 의견과 실제 보유·관측 수치, 롱 청산과 신규 쇼트, 총노출과 순노출을 구분한다. 데이터가 부족하면 ‘판단 자료 부족’으로 발행한다. 명목 규모나 순위가 다른 지표를 임의의 단일 점수로 합산하지 않는다. 국내 신호·매매 엔진의 점수를 자동 변경하지 않는다.

## 독립적인 후보 수집

GitHub Actions `global-position-discovery.yml`은 매일 23:05 UTC(한국시간 다음날 08:05), 최초 코드 반영, 수동 실행에 공개 RSS를 조회한다. Google News 검색 6범주와 Reddit 3채널이다. 현재 원문 접근 범위를 넘어서는 Reddit 전체 검색 또는 유료 데이터 사용을 보장하지 않는다. 성공·실패와 실제 발견 개수를 보고서에 남긴다. 후보가 없다고 전체 언급이 없다고 판단하지 않는다.

이 경로는 저장소 자체의 `GITHUB_TOKEN`으로 후보 파일만 커밋한다. GPT 분석 경로의 권한 확인과 별개이며 ChatGPT의 향후 승인 요청을 우회하거나 영구 해제하지 않는다. GitHub 예약 실행도 부하에 따라 지연될 수 있다.

## 데스크톱 수신과 보존

프로그램 시작 시 새 완료본을 확인하고, 오전 8시 기준일 전환 후 완료본을 기다린다. 작업이 끝나지 않았거나 수신에 실패하면 이전 보고서를 유지하고 발행 대기·이전 자료·자료원 실패를 표시한다. 보고서 확인은 백그라운드에서 수행한다. 미완료 시 5분 후 재시도하며 분석과 후보가 모두 수신되면 다음 기준일 전까지 자동 조회를 쉬고, 자료갱신으로 수동 재확인할 수 있다.

PC에서는 `global_position/report.json`, `discovery.json`과 `history.sqlite3`에 실제 수신본을 보존한다. 수신하지 못한 과거 날짜를 모두 자동 복원하는 기능은 포함하지 않는다. 원격 날짜별 보고서는 위의 `reports/`에 남는다. 진단 ZIP에는 최신 수신본과 요청 점검 기간에 수신한 보고서 이력이 포함된다. 발행시각과 PC 수신시각을 구분한다.

검증기는 규격·해시·시각·출처 등급·참조 관계를 확인한다. 내용의 사실성을 보증하는 전자서명이나 금융 예측의 검증은 아니다. 공개 저장소이므로 계정 키, 원본 로그, 비공개 자료를 올리지 않는다.

## 발행 절차

현재 계약 파일과 작성 지침을 읽고 보고서를 생성한다. Python stdlib로 `seal`, `validate`, `markdown`을 호출하고 `python3 scripts/validate_global_position.py <report.json>`을 통과시킨다. 날짜별 JSON/Markdown을 보존하고 최신 JSON과 Markdown을 같은 Git 트리 커밋으로 반영한다. 최신 브랜치와 이전 `latest.json`을 확인하여 오래된 재시도 결과로 새 보고서를 덮어쓰지 않는다. 게시 후 원격 JSON을 재검증한다. 경로를 추가할 때 기존 국내 보고서 파일을 변경하지 않는다.

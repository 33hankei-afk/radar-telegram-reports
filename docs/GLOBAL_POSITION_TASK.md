# 글로벌 포지션 일보 작성 지침

사용자 요청: 시장스캐너의 해외 커뮤니티에 핵심 3대상과 글로벌 헤지펀드 포지션 관련 언론·커뮤니티를 종합한 한국어 일보를 발행하라.

1. 실행 시각을 Asia/Seoul로 확정한다. 저장소 `33hankei-afk/radar-telegram-reports`에서 이 지침, `scripts/global_position_contract.py`, `schema/global_position_v1.schema.json`, `global-position/latest.json`, 후보 파일을 읽는다. 이전 보고서는 입장 변화 비교와 과거 관점 유지에 쓴다. 후보 파일은 검색 출발점이며 원문 검증을 대신하지 않는다.
2. 최근 24시간의 신규 자료를 검색하라. Shawn Tuteja의 AI/M7·옵션·변동성 관점, Michael Hartnett/BofA Flow Show의 자금흐름·과열·현금, PIMCO의 Ivascyn/Balls/Wilding 등 금리·채권·조달 전망을 각각 확인한다. 새 발언이 없으면 없다고 표시하라. 개인 3명이라고 부르지 않는다.
3. 이들 외에 글로벌 헤지펀드·프라임브로커의 롱/숏·gross/net·deleveraging, 롱 청산/신규 쇼트/쇼트커버, CTA·변동성 목표·딜러 감마, 펀드/ETF 자금흐름, 국채 베이시스·레포·마진·엔 캐리 관련 기사를 확인하라. 공식 은행·운용사·규제기관·거래소 발표/인터뷰, 신뢰할 만한 언론을 우선한다. 공개 Reddit·투자 커뮤니티 언급도 찾되 독립 검증 전에는 주장으로 분리한다. CFTC COT·13F 등이 나와도 실제 관측일과 공시 지연, 13F의 쇼트/현금 미포함 등 한계를 남긴다.
4. 원문을 열어 확인한 부분만 한국어로 요약한다. 원문 URL, 발행일/시각(확인 시), 실제 발언/관측일(확인 시), 발언자·기관, 의견/보도된 흐름/관측 수치/미검증 주장, 근거 등급, 방향, 메커니즘을 보존한다. 확보하지 못한 게시시각이나 발언일을 만들어내지 않는다. 유료 벽·미접근·부분 본문을 밝힌다. 제목만 확인한 자료는 `headline_only`+`unverified`, 커뮤니티는 `community`이며 판단 근거로 쓰지 않는다. 재전송은 같은 `event_key`로 묶고 단일 사건을 독립된 다수 의견으로 집계하지 않는다.
5. `window_start_kst`는 실제 취합 종료 시각에서 24시간 전, `window_end_kst`는 실제 취합 종료 시각, `generated_at_kst`는 실제 발행 시각이다. `date_kst`는 발행일이다. 시간대는 명시한다. 이 구간의 새 게시물은 `entries`에 넣고, 이전 관점은 최대 30일 전의 `context_entries`에 담아 이전 자료임을 표시한다. 날짜만 확인된 경계일 자료는 신규 근거로 쓰지 않는다. 재수집·재전송을 새 발언으로 표시하지 않는다.
6. `assessments`에 `pressure`, `ai_positioning`, `liquidity`, `korea_path`를 작성한다. 각각 label, confidence, summary, evidence_ids, counter_ids, limitations가 필요하다. 매수·매도 압력, AI·반도체, 금리·조달·유동성, 한국장 전달 경로를 짧고 구체적으로 추론한다. 관측자 의견/표본 데이터/전체 펀드 실재 포지션을 구분하고 반대 근거를 적극 확인한다. 순노출 감소를 언제나 신규 쇼트로, 국채 매수를 언제나 주식 매도로 해석하지 않는다. 한국 관련 데이터가 없으면 조건부 경로라고 표시한다. 근거가 없으면 label을 정확히 ‘판단 자료 부족’으로 하고 evidence_ids=[]로 둔다. 인과관계·승률·매매 금액을 확인 없이 산출하지 않는다.
7. `core_targets`는 계약의 TARGETS 3개를 그대로 유지하고 summary_ko/change/evidence_ids를 붙인다. 새로운 발언이 없어도 마지막 확인 날짜와 과거 관점임을 명시한다. 입장 변화를 주장하려면 서로 다른 시점의 독립 원문 두 개 이상이 필요하다. 미확인이면 change='미확인'이다. 원문 두 개가 동일 사건의 재전송이면 변화 증거가 아니다.
8. `coverage`에 각 핵심 대상, 확장 포지션 범주, 언론, 커뮤니티의 확인 범위와 checked/partial/blocked/failed, 실패 사유를 남긴다. `coverage_note`에는 새 자료/이전 자료/미확인 범위를 요약한다. 새 발언 0건과 수집 실패를 구분한다. 실제로 확인을 끝낸 범위에 한해 complete=true를 쓴다. 전부 실패하면 complete=false, 판단 자료 부족으로 내고 이전 완료본을 새 완료본처럼 바꾸지 않는다.
9. producer='gpt_verified', schema='global_position_v1'로 작성한다. 내려받은 계약의 `seal`, `validate`, `markdown`을 사용하여 표준 JSON 해시를 생성하고 검증하라. 검증에 실패하면 자료를 정정하고 통과하기 전에는 발행하지 않는다. 필요한 키가 없다고 임의로 코드를 바꾸거나 검증을 생략하지 않는다.
10. 검증된 JSON/Markdown을 `global-position/reports/YYYY-MM-DD.json`과 `.md`, `global-position/latest.json`과 `.md`로 같은 Git 트리 커밋에 발행하라. 원격 최신 브랜치를 읽고 기존 트리를 바탕으로 허용된 4경로만 바꾸고 expected_sha를 사용해 갱신하라. 더 최신 발행본이 이미 있으면 역행 덮어쓰기를 하지 않는다. 발행 후 원격 파일을 다시 확인하라. 기존 루트의 국내 보고서, `reports/`, 발견 후보 폴더, 예약작업은 수정하지 않는다. 키나 사용자 로그, 유료 원문 전문을 공개 저장소에 쓰지 않는다.
11. 사용자에게 한국어로 핵심 판단, 달라진 관점, 확인 못한 자료, 날짜별 보고서 링크와 GitHub 발행 성공/실패를 정확하게 알린다. 실패 시 결과를 보존하고 실패를 보고하라. 기존 정기 작업을 해제하거나 중복 작업을 생성하지 않는다. 플랫폼이 요구하는 권한 승인을 완료한 것으로 가장하지 않는다.
